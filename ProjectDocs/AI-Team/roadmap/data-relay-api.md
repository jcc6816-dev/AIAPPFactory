# 数据中继能力路线图

> 版本：0.1
> 状态：PROPOSED
> 来源：Gemini 对团队工作模式的优化建议

## 1. 背景

当前 GSC 和 GA4 数据主要依赖 Mike 手动导出或截图，再放入项目目录供 Codex / Gemini 分析。

短期内这是安全、可控的方式，但长期会产生问题：

- Mike 被绑定在机械数据搬运上。
- 数据更新不够稳定。
- 周复盘依赖人工记忆。
- Data Agent 难以形成固定节奏。

## 2. 目标

规划一个只读、脱敏、受限的数据中继能力，让 Codex 或未来 Data Agent 可以读取聚合后的增长数据，用于周报、机会分析和趋势复盘。

## 3. 可读取的数据范围

首版只考虑聚合数据：

- GSC 查询词汇总。
- GSC 页面汇总。
- GSC 日期趋势。
- GA4 获客渠道汇总。
- GA4 关键事件汇总。
- 站内 Growth 事件聚合。

禁止读取：

- 用户级明细。
- 邮箱、姓名、IP、表单提交内容。
- 订单、支付、账单。
- OAuth token、API key、cookies。
- 原始 webhook 日志。

## 4. 安全要求

必须满足：

- 只读。
- 只返回聚合数据。
- 支持最小时间窗口和最大时间窗口限制。
- 输出字段白名单。
- 访问日志。
- 不把凭证写入仓库。
- 不允许 Gemini 直接读取密钥。
- 首版由 Codex 调用，Gemini 只能读取 Codex 输出的脱敏报告。

## 5. 建议阶段

### 阶段 1：继续人工导出

适用当前阶段。

Mike 按需提供 GSC / GA4 截图或导出，Codex 做复盘。

### 阶段 2：本地只读脚本

Codex 建立本地脚本，读取 Mike 放入的导出文件，生成统一 Markdown 周报。

不连接外部账号，不处理 secrets。

### 阶段 3：受限 API 或服务账号

在 Mike 明确批准后，研究是否接入 GSC / GA4 只读 API。

要求：

- 单独凭证。
- 最小权限。
- 只读。
- 不进入 Gemini 任务上下文。
- 输出脱敏汇总。

### 阶段 4：Data Agent

只有当阶段 2/3 稳定后，才考虑让 Data Agent 读取数据中继结果。

Data Agent 不能直接持有外部账号凭证。

## 6. 当前结论

该建议有长期价值，但不应立即实现外部账号 API 接入。

当前推荐：

1. 先保持 Mike 手动提供关键数据。
2. Codex 建立统一数据复盘模板。
3. 后续用本地只读脚本减少重复整理。
4. 等增长节奏稳定后，再评估 GSC / GA4 Data Relay API。
