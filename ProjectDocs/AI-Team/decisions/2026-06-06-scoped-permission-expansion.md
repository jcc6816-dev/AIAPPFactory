# 决策记录：Gemini 细粒度权限扩展

## 日期

2026-06-06

## 背景

在博客、模板页、SEO 和增长任务中，如果 Gemini 完全不能读取代码，容易出现“盲猜”或内容事实不精确。例如 Webhook 重试次数、模板字段、FAQ 渲染方式、CTA 入口等信息，往往需要有限读取代码才能判断。

同时，直接开放 `Code/**` 写权限、部署权限或 Git 权限风险过高，不符合当前 AI-Team 安全边界。

## 决策

采用“放宽只读、谨慎放写、沙箱验证”的分层权限：

1. `CODE_READ_SCOPED`：允许 Gemini 只读查看任务列出的具体代码文件。
2. `CONTENT_WRITE_SCOPED`：允许 Gemini 修改任务列出的内容、Markdown 或非核心配置文件。
3. `SANDBOX_VERIFY`：允许 Gemini 在明确命令范围内运行低风险只读验证。

## 不开放的权限

- 不开放泛目录 `Code/**` 读写。
- 不开放业务逻辑代码写权限。
- 不开放认证、支付、账单、数据库迁移、生产部署脚本修改。
- 不开放 Git commit。
- 不开放生产部署。
- 不开放 secrets、tokens、cookies、外部账号和用户隐私数据读取。

## 申请机制

如果 Gemini 在执行中发现需要额外读取某个代码文件，必须在报告中写：

```text
[REQUEST_READ: /absolute/path]
```

Mike 或 Codex 批准后，才能创建新任务或更新任务范围。

## 试点建议

优先试点：

- 博客事实核验任务。
- 模板 FAQ / CTA / 内链审计任务。
- SEO 页面结构检查任务。
- GA4 / Growth 事件实现前设计任务。

暂不试点：

- 认证、支付、账单、数据库迁移。
- 生产部署脚本。
- 表单提交数据、Webhook secrets、用户数据。
