# 2026-06-07 Codex 低可用生产增长冲刺计划

## 适用窗口

- 时间：2026-06-07 到 2026-06-12
- 状态：Codex 低可用，Mike + Gemini 主推进
- 目标：不再只产出文档和候选任务，而是每天推动公开页面、可发布内容、GSC/GА4 或外部发现信号发生真实变化。

## 冲刺原则

1. 每天至少完成 1 个生产可见动作，或 1 个可由 Mike 当天发布的生产准备动作。
2. Gemini 不再无限堆 Backlog，每天最多新增 1-2 个 `PROPOSED`。
3. 每个 Gemini 产出必须绑定：
   - 公开 URL 或待发布 URL
   - 目标关键词
   - CTA
   - 发布后检查方式
   - GSC 或 GA4 后续动作
4. Mike 的工作不只是“等 Codex”，而是负责发布、GSC、GA4、外部提交和低风险人工复核。
5. 高风险代码、部署、认证、支付、数据库、生产脚本仍等待 Codex。

## 本周期量化目标

到 2026-06-12，至少完成：

- 发布 2-3 篇高质量 SEO 文章。
- 完成 2 个外部目录或社区曝光准备/提交。
- 完成 1 轮 GSC 数据解读和下一步页面优先级判断。
- 完成 1 份模板页 FAQ / CTA 文案包，供 Codex 恢复后直接落地。
- 完成 1 份 GA4/Growth 事件实现优先级清单，供 Codex 恢复后直接实现。
- 形成 Codex 恢复后的 Top 5 实现任务清单。

## Mike 每日工作量

建议每天投入 1.5-2.5 小时，周末可 3-4 小时。

Mike 负责：

- Admin 后台发布文章。
- 发布后打开生产 URL 检查页面。
- GSC 请求索引。
- GA4 截图或导出事件数据。
- 外部目录提交。
- 对 Gemini 低风险内容做人工确认。
- 记录完成事项编号或截图反馈。

## Gemini 每日工作量

建议每天安排 4-6 小时等效工作。

Gemini 负责：

- 写可发布草稿，不只写策略。
- 做发布后检查清单。
- 做 GSC/GA4 数据解读。
- 做内容质量审计。
- 做低风险候选任务提案。
- 每天写 `daily-summary-YYYY-MM-DD.md`。

## 每日计划

### Day 1：发布第一篇通过审稿的博客

目标：

- 把 `AI-TASK-2026-006-014` 中的 Webhook 博客变成生产公开页面。

Gemini 工作：

- 从 `AI-TASK-2026-006-014` 中提取第一篇文章，整理为后台可粘贴版本。
- 输出发布字段：
  - slug
  - title
  - description
  -正文
  - FAQ
  - CTA
  - internal links
  - 发布后检查清单
- 检查是否还有产品事实风险。

Mike 工作：

- 在 Admin 后台创建并发布文章。
- 打开生产 URL 检查正文、发布日期、链接、CTA。
- 在 GSC 请求索引。
- 将结果反馈给 Gemini。

验收：

- 文章生产 URL 可访问。
- 页面有真实发布日期。
- GSC 已请求索引或记录因配额限制待提交。

Mike 工作：

验收：

- 第二篇上线，或已形成可发布草稿并设定发布时间。
