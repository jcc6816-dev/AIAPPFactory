# GenForms.ai AI 团队操作系统

> 版本：0.2
> 日期：2026-06-06
> 范围：Mike、Codex、Gemini，以及未来参与 GenForms.ai 的 AI Agent。
> 状态：TEAM_REVIEWED_PENDING_MIKE_CONFIRMATION

## 1. 为什么需要这套操作系统

GenForms.ai 不能继续只靠“看到一个点就改一个点”的方式推进。当前阶段已经进入商业化增长和产品承接并行的阶段，需要用团队目标、里程碑、周计划、任务文件和复核报告来形成可持续执行。

这套操作系统用于回答：

- 我们共同认可的目标是什么？
- 目标为什么值得做？
- 目标如何拆成阶段？
- 每周谁做什么？
- Gemini 做完后如何验收？
- 哪些事情必须 Mike 决策？
- 哪些经验需要沉淀？

## 2. 团队使命

把 GenForms.ai 打造成一个 AI 原生的表单创建与数据收集产品，让用户可以从一句话快速生成、发布、分享和收集表单，并最终形成可持续的流量、注册、使用和付费路径。

当前商业漏斗：

```text
搜索曝光
-> 页面点击
-> 创建 CTA 点击
-> 注册或登录
-> 创建表单
-> 发布表单
-> 收到真实提交
-> 付费升级或形成高质量线索
```

不服务该漏斗、不提升稳定性、不降低风险、不增强产品质量的任务，应暂缓。

## 3. 角色分工

### Mike

角色：Owner、商业决策人、最终人类确认人。

职责：

- 确认商业目标和时间窗口。
- 提供 Agent 无法安全访问的外部数据，例如 GSC、GA4、目录提交状态。
- 审批重大产品方向、定价、公开发布、新 Agent 权限和外部推广节奏。
- 决定重大目标是继续、暂停还是调整。

### Codex

角色：项目经理、产品/工程大脑、规划者、复核者、验收闸门。

职责：

- 把商业目标拆成里程碑、周计划和任务说明。
- 维护团队文档、任务看板、决策记录和复核报告。
- 给 Gemini 或未来 Agent 分配明确任务。
- 复核报告、代码、内容、SEO 质量和部署准备情况。
- 保护范围、安全、SEO 质量和生产稳定性。

### Gemini

角色：执行者、研究者、内容初稿作者、低风险审计助手。

职责：

- 读取任务文件，并只在允许范围内执行。
- 输出中文执行报告。
- 不接触 secrets、部署、Git 提交和禁止文件。
- 遇到不确定点时报告阻塞，不自行扩大范围。
- 接受 Codex 复核作为最终验收。

### 未来 Agent

未来新增 Agent 必须解决明确瓶颈，而不是为了“人多”而增加。

可考虑角色：

- SEO Research Agent：关键词、竞品、GSC 机会分析。
- Content Agent：博客草稿、目录文案、Solution 页面草稿、翻译。
- QA Agent：浏览器检查、E2E 测试、生产烟测、回归报告。
- Data Agent：GA4/GSC 周报、漏斗分析、指标复盘。

所有未来 Agent 都必须通过任务文件和报告协作。

## 4. 目标对齐规则

目标不是 Codex 写出来就自动生效。

重大目标必须经历：

```text
DRAFT -> REVIEWING -> TEAM_ALIGNED -> ACTIVE -> REVIEWED -> CLOSED
                         -> REVISE
```

状态含义：

- `DRAFT`：Codex 提出目标草案。
- `REVIEWING`：Mike 和执行 Agent 正在审阅。
- `TEAM_ALIGNED`：Mike、Codex 和至少一个执行 Agent 已认可。
- `ACTIVE`：团队开始正式按该目标执行。
- `REVIEWED`：目标已进行阶段复盘。
- `CLOSED`：目标完成、过期或被主动停止。
- `REVISE`：目标不清楚、不现实或未达成共识，需要修改。

目标进入 `TEAM_ALIGNED` 前必须包含：

- 想要达成什么结果。
- 为什么具有商业意义。
- 用哪些指标证明进展。
- 时间窗口是否合理。
- 哪些事情明确不做。
- 谁负责哪部分。
- 哪些风险会让目标失效。

## 5. 计划层级

团队使用五层计划：

1. 目标：商业结果和时间窗口。
2. 路线图：达成目标的主要路径。
3. 里程碑：阶段目标和验收标准。
4. 周计划：每周工作计划。
5. 任务：具体负责人、范围、报告路径和验收标准。

任何每日任务都应能追溯到目标、路线图、里程碑或周计划。

## 6. 每周节奏

### 周一：指标复盘与周计划制定

输入：

- GSC 索引页、曝光、点击、查询词、页面。
- GA4 或产品事件。
- Mike 完成的外部动作。
- 上周已完成工作和复核意见。

输出：

- 更新后的周计划。
- 优先级任务列表。
- Gemini 任务文件。
- Mike 待办清单。

### 周二到周四：执行

规则：

- Codex 分配任务说明。
- Gemini 执行并写中文报告。
- Codex 复核报告并更新看板。
- Mike 只处理需要外部账号或商业判断的动作。

### 周五：复盘

输出：

- 本周哪些动作有效。
- 哪些动作无效。
- 哪些指标变化。
- 哪些任务继续、暂停或停止。
- 哪些经验应沉淀到 GenExperience。

## 7. 任务分配原则

适合交给 Gemini 的任务：

- 调研型工作。
- 内容或文案审计。
- SEO 页面质量审计。
- GSC/GA4 导出数据分析。
- 低风险文档整理。
- 需要广泛阅读但不需要生产动作的任务。

适合走 `FAST_TRACK` 的任务：

- 极低风险错别字修正。
- 明显路径、编号、状态修正。
- 小范围文档格式调整。
- 不涉及生产、不涉及核心代码、不影响 SEO 冻结页面的微小修补。

`FAST_TRACK` 仍需 Codex 授权，并需要简短中文报告。

适合 Codex 自己做的任务：

- 核心产品架构。
- 触碰认证、支付、数据库、发布、生产的代码实现。
- 部署和部署后验证。
- 最终 SEO 质量闸门。
- Git 提交、分支或发布决策。

适合 Mike 做的任务：

- 外部账号操作。
- GSC 手动提交。
- GA4 UI 设置。
- 产品定价决策。
- 需要人类商业判断的取舍。
- 新 Agent 权限审批。

## 8. 验收机制

Gemini 做完不等于任务完成。

任务完成必须满足：

- Gemini 在指定路径写入中文执行报告。
- Codex 复核范围、质量、验证和风险。
- Codex 写入中文复核报告。
- 看板状态更新为 `REVIEW_PASSED`、`REVIEW_REJECTED` 或 `NEEDS_HUMAN_INPUT`。

代码变更、生产部署、公开发布、价格变化和敏感数据访问，需要 Codex 复核；重大事项还需要 Mike 确认。

## 9. 决策记录

重要选择必须记录在 `decisions/`。

需要记录的事项：

- 目标变化。
- 定价变化。
- SEO 策略变化。
- Agent 权限变化。
- 产品范围变化。
- 部署流程变化。
- 团队可能反复争论的决定。

## 10. 指标纪律

团队不能只靠感觉推进。

主要指标：

- GSC 曝光。
- GSC 点击。
- 已索引页面。
- 重点查询词排名。
- CTA 点击。
- 注册率。
- 表单创建率。
- 表单发布率。
- 首次收到提交。
- 付费升级或高质量线索。

指标解释规则：

- 不因一天 SEO 数据过度反应。
- 接近第一页的页面优先小改，并观察 3-7 天。
- 新发布页面按 D0、D1-D3、D3-D7、D7 节奏检查。
- 记录哪个任务带来了哪个结果，让团队持续学习。

## 11. 质量闸门

SEO 和内容工作必须遵守：

- `ProjectDocs/Operations/google_seo_quality_rules.md`
- `ProjectDocs/Operations/genforms_traffic_growth_plan.md`
- `ProjectDocs/Operations/genforms_growth_operating_guideline.md`

生产工作必须包含：

- 范围检查。
- 必要的构建或定向测试。
- SEO 页面变更后的生产 SEO Gate。
- 生产发布后的验证。
- 失败回滚或修复路径。

## 12. 当前优先级

在新的正式目标替换之前，团队优先处理：

1. 可持续 SEO 流量发现。
2. 访客激活进入表单创建。
3. 发布表单后的真实使用和提交。
4. 清晰的免费到付费升级理由。
5. 生产稳定和安全部署。
