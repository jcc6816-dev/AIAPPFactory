# GenForms 竞品借鉴执行方案（MVP）

更新时间：2026-08-09
状态：待负责人确认后按阶段执行；本文件本身不授权上线或功能扩张。
适用范围：GenForms 的“进入创建 → AI 生成 → 发布 → 首次结果”核心闭环。
产品基线：[PRD V1.1](../PRD/PRD-V1.1-AI-Form-Generator.md) 与 [核心闭环质量门禁](./genforms-core-loop-reference-and-quality-gates-2026-08-09.md)。

## 1. 为什么要有这份方案

当前问题不是缺少竞品功能，而是用户很难在第一次使用中确信三件事：

1. AI 是否按我的意图创建了正确的表单；
2. 发布后的链接是否已经真实可用；
3. 第一条数据是否被安全、可靠地收到。

竞品研究只服务于解决这三件事。任何不能缩短、澄清或验证首成功闭环的能力，都不进入本方案。

## 2. 成功定义与硬边界

### 成功定义

首次访问者能在一个会话内完成：选择活动报名模板或直接描述需求 → 得到与上下文一致的表单 → 发布公开链接或二维码 → 完成一条不会触发外部通知的 TEST → 看见该条结果。

### 不借鉴、不做的范围

- 不做拖拽式表单编辑器、条件逻辑、支付、文件上传、保存后继续、复杂分析。
- 不引入 OCR、Skill、工作流、Agent、自动化运维等非 MVP 表述或入口。
- 不复制开源竞品的代码、视觉资产、文案或专有交互；仅研究公开行为与信息架构。
- 不因单一截图、单条录屏或聚合漏斗就开始大改；冷启动阶段须以 Clarity 外部会话验证。

## 3. 竞品分工：谁解决什么问题

| 参考对象 | 研究结论 | GenForms 可借鉴的最小原则 | 明确不借鉴 |
| --- | --- | --- | --- |
| Typeform | 默认逐题作答；进度用于解释完成位置；必要时可合并兼容题目，但不建议堆题。 | 活动报名默认一题一页；题号、总题数、进度与下一步保持稳定。 | 条件路径、复杂编辑器、其视觉语言。 |
| QuillForms | 对话式表单以“单题、低负担、连续前进”为中心，手机端需足够大的操作目标。 | 当前题只有一个主动作；按钮可触达；题目切换后反馈明确。 | 大量题型、计算器、评分、支付、完整功能矩阵。 |
| Formbricks | 分享链接是分发开始，不是任务结束；结果可见性决定创建者是否感到成功。 | 发布页默认展示链接、打开、复制、二维码；TEST 后直达首条结果。 | 完整调研平台、分析体系、团队协作/权限模型。 |
| HeyForm | 创建、主题、发布可按清晰阶段组织。 | 主题仅保留 3 套，且在生成前后保持一致。 | 拖拽编排与大而全设置面板。 |

## 4. 借鉴筛选机制（防止走偏）

每个候选能力先由产品经理填写下表，四项全部为“是”才可进入设计；否则记录为“暂不做”。

| 判断问题 | 通过标准 |
| --- | --- |
| 是否解决首成功链路的已知断点？ | 能对应创建理解、生成、发布、首次测试或首条结果中的一个具体问题。 |
| 是否能用一个小改动交付？ | 不新增复杂数据模型、权限模型或非 MVP 基础设施。 |
| 是否能定义可观察的验收信号？ | 有明确界面、交互、测试或 Clarity 行为证据。 |
| 是否不改变 MVP 承诺？ | 不出现工作流、OCR、Agent、Skill、复杂编辑器等范围外语义。 |

额外否决条件：需要复制 AGPL 代码、没有真实用户问题、只能用“更好看”描述、会让一个页面出现两个以上主动作。

## 5. 分阶段执行路线

每阶段完成后先做隔离环境体验验收，再由负责人确认是否进入下一阶段。不得并行堆叠多个阶段。

### 阶段 0：基线与守门（当前）

**目的**：把已经确认的体验原则变成不可回退的质量门禁。
**借鉴来源**：Typeform、QuillForms、Formbricks。

| 工作项 | 最小交付 | 验收标准 | 负责人 |
| --- | --- | --- | --- |
| 入口语义一致 | 普通入口是通用创建；模板入口保留模板名称、字段数与预览上下文。 | 首页普通入口、活动模板入口均无语义错位。 | 产品经理 + 工程负责人 |
| 单题流基线 | 一题、一主按钮、稳定题号/进度；主按钮最小 44px。 | 390×844、1440×900 无横向溢出；首题和下一步可理解。 | UX 负责人 + 测试负责人 |
| 发布安全基线 | 公共链接、打开、复制、二维码默认可见；TEST 明确不触发外部通知。 | 发布→TEST→结果可串行完成；服务端鉴权不允许游客绕过。 | 工程负责人 + 测试负责人 |

**完成条件**：两条入口的完整自动化与手工回归通过；无 P0/P1；保留截图、控制台结果和测试记录。
**当前状态**：入口语义和响应式自动化回归已完成；完整安全与真实持久化回归以隔离环境记录为准。

### 阶段 1：生成后的可控感

**用户问题**：用户不知道 AI 是否真正理解需求，或不敢立即发布。
**借鉴原则**：竞品把“可见的结果摘要”置于高级配置之前。

**最小方案**：生成完成页只展示 4 个可理解的摘要：表单名称、字段数量、当前主题、填写模式；提供一个主动作“发布并获取链接”和一个次操作“继续调整”。

**不做**：字段拖拽、规则编排、复杂设置侧栏、无限主题。
**验收**：

- 描述“活动报名”后，摘要与预览字段一致；
- 发布前可理解“链接会公开可访问”；
- 一个页面只有一个视觉主动作；
- 失败/重试时保留用户原始描述。

**进入条件**：阶段 0 全通过，且至少 3 条合格外部 Clarity 会话或 3 位受控测试者表现出生成后停顿、反复查看或未发布。

### 阶段 2：发布与首个结果的完成感

**用户问题**：发布后不知道下一步，或不知道链接/二维码/结果是否真实有效。
**借鉴原则**：Formbricks 式的“分享 → 首次响应 → 可见结果”任务闭环。

**最小方案**：

1. 发布页默认完整展示公开链接与可扫描二维码；
2. 两个并列次操作：“打开表单”“复制链接”；
3. 唯一主动作：“开始免费测试”；
4. TEST 提交后进入首条结果页，回显字段、`TEST 已保存`、`外部通知已跳过`，并给“复制链接/查看结果”下一步。

**不做**：社交分发矩阵、复杂分析报表、团队协作邀请、营销自动化。
**验收**：链接可打开、复制有效、二维码可扫；TEST 不扣额度且不发 Webhook/邮件；首条结果可见。

**进入条件**：阶段 1 不引入新的 P1；或 Clarity/受控测试证明发布后离开或无法辨认下一步是主要断点。

### 阶段 3：移动端可靠性

**用户问题**：在手机上键盘、底部按钮、题目切换容易破坏连续填写。
**借鉴原则**：QuillForms 的连续答题节奏，而非视觉仿制。

**最小方案**：

- 下一题/提交操作区始终拥有清晰优先级；
- 输入后可用键盘 Enter 前进（多行文本除外）；
- 校验错误在当前题、当前输入附近；
- 切题后焦点移至题干或第一个可编辑输入；
- 实机软键盘不遮挡唯一主动作。

**不做**：复杂动画、聊天机器人拟人化、条件分支。
**验收**：iOS Safari 与 Android Chrome 各完成一次 4–6 题 TEST；无按钮遮挡、无横向滚动、无焦点丢失。

**进入条件**：阶段 2 通过，且移动端真实会话或受控测试出现一次可复现障碍。

### 阶段 4：有限的主题与可信分享（后置）

**用户问题**：发布的公开表单缺少品牌感，分享时辨识度不足。
**借鉴原则**：HeyForm 的主题可见性和 Typeform 的发布一致性。

**最小方案**：保留 3 套预设主题；创建预览、公开表单与二维码分享页使用同一主题。为公开链接补齐标题、描述和 OG 图。

**不做**：自定义 CSS、主题市场、无限配色、嵌入式设计器。
**验收**：主题选择跨创建/发布/公开页一致；分享卡片能正确展示且不含演示个人信息。

**进入条件**：阶段 3 通过，且 SEO/增长证据显示分享页曝光或外部分享已具备一定量级。

## 6. 固定交付流程

每一个阶段都按以下顺序执行：

1. **发现**：产品经理写明用户问题、证据来源和借鉴原则。
2. **方案**：UX 输出低/高保真图与状态说明；工程负责人给出文件、数据、API、风险计划。
3. **确认**：负责人只确认本阶段最小范围，不默认授权下一阶段。
4. **实现**：仅在隔离环境修改；不部署生产。
5. **验收**：测试负责人完成两个入口、两个视口、完整链路；UX 复核信息层级；工程复核权限与副作用。
6. **学习**：增长负责人以最近 7 天 Clarity 合格外部会话复查，记录“保留/修正/停止”。

任何一阶段出现 P0（鉴权、公开数据、创建/发布/提交失效）立即停止后续功能，先修复并回归。

## 7. 指标与证据口径

冷启动阶段不设虚假的数值目标，也不以聚合漏斗单独决策。采用以下分层证据：

| 问题 | 首选证据 | 辅助证据 | 决策阈值 |
| --- | --- | --- | --- |
| 入口是否理解 | Clarity 外部会话的落地页→创建行为 | 受控测试观察 | 同一问题在 ≥3 条合格会话重复才排入下一阶段。 |
| 生成是否受挫 | 创建页停顿、重复点击、错误状态 | 无 PII 事件：`forms_new_view`、`primary_action`、`ai_generate_submitted` | 发现 P0/P1 可立即热修；其余需重复证据。 |
| 发布是否完成 | 发布页链接/二维码/TEST 行为 | `form_created`、测试结果事件 | ≥3 条合格会话同一断点，才实施体验改动。 |
| 填写是否顺畅 | 手机录屏中的键盘/按钮/校验行为 | 受控实机测试 | 单次可复现的遮挡或无法前进即 P1。 |

Clarity 审计前置：管理员提供只读访问；排除内部、localhost、机器人、≤1 秒会话；不记录提示词、邮箱等 PII。

## 8. 角色责任与否决权

| 角色 | 责任 | 有权阻止的事项 |
| --- | --- | --- |
| 产品经理 | 维护范围、证据与阶段排序。 | 没有用户问题或超出 MVP 的功能。 |
| UX 负责人 | 输出交互状态、响应式和可访问性验收。 | 多主动作、手机不可达、状态不清。 |
| 工程负责人 | 服务端鉴权、数据副作用、测试与回滚。 | 仅靠前端限制、未隔离的真实写入。 |
| 测试负责人 | 两入口/两视口/完整链路回归。 | P0/P1 未修复或证据不完整。 |
| SEO 负责人 | 保护可抓取性与 MVP 意图一致性。 | 影响 sitemap 健康、索引语义或用范围外内容换流量。 |
| 增长负责人 | Clarity 分层审计与事件口径。 | 用低样本聚合数据作结论。 |
| 负责人（你） | 确认每阶段范围与验收结果。 | 进入下一阶段、生产部署和范围扩张。 |

## 9. 当前待办与决策

### 可以立即执行（不改产品）

1. 固化阶段 0 的自动化回归清单与证据归档；
2. 配置 Clarity 只读访问，完成一次最近 7 天分层审计；
3. UX 用本文件的阶段 1/2 规范评审现有生成完成页和结果页，列出差距，不直接改代码。

### 需要负责人确认后才可实施

1. 阶段 1 的生成结果摘要与发布提醒；
2. 阶段 2 的结果完成页增强；
3. 阶段 3 的移动端交互细节；
4. 阶段 4 的公开分享元数据。

## 10. 置信度与待验证项

- **高置信度**：单题节奏、稳定进度、清晰发布/TEST/首条结果是当前核心闭环的正确借鉴方向；公开竞品资料与现有本地回归均支持。
- **中置信度**：生成结果摘要是否是当前首要断点；须经 Clarity 或受控测试确认后实施。
- **待验证**：真实外部用户在发布、填写或分享中的主要流失点；目前没有可调用的 Clarity 只读访问，不能用猜测替代。
