# GenForms 核心闭环竞品参考与质量门禁

更新时间：2026-08-09
适用范围：GenForms MVP 的“进入创建 → 生成 → 发布 → 首次测试结果”闭环。
不适用范围：OCR、Skill/工作流编排、复杂编辑器、自动化运营等非 MVP 能力。

## 目标

把竞品研究转化为可验证的产品质量标准，而不是复制功能或视觉。当前阶段只追求一个结果：首次使用者能明确创建一张表、公开分享，并看见一条安全的测试结果。

## 参考对象与借鉴边界

| 参考对象 | 可研究的问题 | 不做的事 |
| --- | --- | --- |
| [Formbricks](https://github.com/formbricks/formbricks) | 模板进入、发布与结果闭环的任务结构 | 不复制 AGPL 代码；不引入其完整调研/分析平台 |
| [HeyForm](https://github.com/heyform/heyform) | 创建到发布的状态组织、主题与分享信息层级 | 不扩张为可视化拖拽编辑器；不复制 AGPL 代码 |
| [QuillForms](https://github.com/quillforms/quillforms) | 单题流节奏、键盘/移动端答题与连续反馈 | 不把题型/条件逻辑扩展作为本阶段目标 |
| [Typeform Embed](https://github.com/Typeform/embed) | 公开链接、嵌入与回调的清晰语义 | 不复制专有产品体验或承诺未实现能力 |

以上对象用于行为与信息架构比较。所有开源仓库的许可证必须在引入任何源代码前由工程负责人单独复核。

## 首成功闭环的产品合同

| 阶段 | 使用者应理解的事 | 唯一主动作 | 验收信号 |
| --- | --- | --- | --- |
| 首页/模板入口 | 我将创建什么；选择模板后会得到对应上下文 | 创建活动报名表 | 入口带入正确模板名称、题目数和预览内容 |
| 创建页 | 描述活动后会生成可继续调整的表单 | 生成报名表 | 可点击、有加载/完成反馈，桌面和手机首屏均能看到主要行动区 |
| 生成完成 | 当前是草稿；发布后链接会公开可访问 | 发布并获取链接 | 发布含公开性提醒，不把发布和后续测试混淆 |
| 发布页 | 链接和二维码已可分享；测试不会触发外部通知 | 开始免费测试表单 | 链接、打开表单、复制、二维码可用且层级清楚 |
| 测试页 | 这是一条安全的内部测试，提交会写入结果面板 | 提交测试结果 | 手机与桌面按钮可见可点；不会触发 Webhook/外部通知 |
| 结果页 | 第一条结果已保存，下一步可查看和分享 | 查看结果 / 复制链接 | 逐字段回显、测试标识清楚、没有误导性计费文案 |

## 交付门禁

每个涉及上述闭环的改动都必须同时满足：

1. **设计门禁**：不新增 MVP 范围外的承诺；一个视图只有一个清晰主动作；公开链接和二维码不藏在二级交互之后。
2. **响应式门禁**：在 390×844 与 1440×900 下，没有横向溢出；关键操作、首题及下一步在可理解的位置；桌面预览具有完整底部边界，不能看起来像被截断的手机页。
3. **链路门禁**：首页普通入口、模板入口均进入一致的创建语义；生成、发布、测试、结果可串行完成。
4. **安全门禁**：游客不能绕过服务端鉴权直接创建或发布；测试提交标记为测试且不触发外部通知；任何真实发布/提交测试须在隔离环境执行并获得授权。
5. **证据门禁**：交付需附桌面和手机截图、自动化测试结果、控制台错误检查，以及已知限制；不能用单张静态截图代替完整链路验证。

### 创建页视觉放行矩阵（新增，强制）

凡修改首页、模板入口、`/forms/new`、发布、测试或结果页的核心布局，必须在候选环境完成以下矩阵；缺任一项不得交给负责人验收，更不得部署生产。

| 编号 | 路径与视口 | 必交证据 | 阻断条件 |
| --- | --- | --- | --- |
| V1 | `/forms/new`，1440×900，Phone 预览 | 截图 + Playwright 结果 | 手机比例失真、上下贴边、被裁切、横向溢出 |
| V2 | `/forms/new`，1440×900，Desktop 预览 | 截图 + Playwright 结果 | 预览缺少底部边界、看起来像手机页、主操作不完整 |
| V3 | `/zh/forms/new`，1440×900，Phone 预览 | 截图 + Playwright 结果 | 任一英文状态/按钮/占位文案残留 |
| V4 | `/zh/forms/new`，1440×900，Desktop 预览 | 截图 + Playwright 结果 | 重复标题、重复阶段提示或中文路径混入英文 |
| V5 | `/forms/new`，390×844 | 截图 + 手动操作记录 | 横向溢出、关键动作需滚动寻找、软键盘后无法继续 |
| V6 | `/zh/forms/new`，390×844 | 截图 + 手动操作记录 | 横向溢出、语言混搭、单一主动作不清楚 |

截图统一归档至 `ProjectDocs/UX-Audit/<日期>-<页面>/`，文件名必须包含语言、视口和状态，例如 `creator-en-desktop-phone.png`。Playwright 的 `creator-visual-gates.spec.ts` 负责结构性门禁（语言、溢出、预览边界与截图附件）；UX 负责人仍需对截图做审美与层级签核，自动化不能替代该判断。

### 问题关闭规则（新增，强制）

每一条由用户、UX 或测试提出的 UI 问题，关闭前必须记录：

1. 可重复路径与严重度；
2. 对应的产品/视觉断言，而非仅描述“调了一点 CSS”；
3. 修复前后截图；
4. V1–V6 中受影响项的回归结果；
5. 产品经理、UX 负责人和测试负责人三方的放行结论。

若任一项未完成，状态只能是“待验证”，不能标记为“已完成”。

## UX 对标补充：单题流与状态反馈

以下规则来自 UX 对 QuillForms 与 Typeform 公开体验的复核，只取与 MVP 直接相关的行为，不复制视觉或代码：

1. 一题、一主动作、一条稳定进度反馈；390×844 与 1440×900 都能同时理解题号、进度、输入区及“下一题/提交”。参考：[Typeform 单题页](https://help.typeform.com/hc/en-us/articles/38099463383188-How-to-add-multiple-questions-to-a-form-page)、[QuillForms Conversational Forms](https://quillforms.com/features/conversational-forms/)。
2. 手机端操作区保持可见，按钮高度至少 44px；软键盘出现后仍可触达，切题后焦点回到题干。参考：[Typeform 移动端创建](https://help.typeform.com/hc/en-us/articles/360057243192-Create-forms-on-mobile)。
3. 生成状态最多三步：“正在理解活动 → 正在生成字段 → 预览已准备好”；主按钮在处理中不可重复触发，失败时保留原输入并可重试。
4. 发布后的首要安全动作是 TEST；结果页必须说明“TEST 已保存 / 外部通知已跳过 / 可继续分享”。
5. 模板上下文贯穿创建与预览：名称、题目数、首题、预览和生成草稿不得回退为无关的通用样例。

上述公开竞品资料的行为定位置信度高；其性能或业务效果并未做独立测评。

## 增长对标补充：分享、首次结果与 Clarity

Formbricks 的可借鉴顺序是“模板 → 预览 → 发布 → 结果 → 分享”，而非增加功能。参考：[Link Survey Quickstart](https://formbricks.com/docs/surveys/link-surveys/quickstart)、[Link Settings](https://formbricks.com/docs/surveys/link-surveys/link-settings)。

- 发布必须由表单所有者执行；结果首屏应可见响应状态、免费测试、公开链接/复制/打开和二维码。
- 测试提交写入 `TEST`，不扣额度、不触发 Webhook、邮件或其他外部通知；完成后直接进入结果面板，能看到该条记录。
- 真实公开提交才进入正式处理与 Webhook。公开分享链接后续可补独立标题、描述与 OG 图，但不是本轮阻断项。

Clarity 真实会话验证的前置条件：

1. 由项目管理员为指定 GenForms 项目提供只读访问，或在 MCP 连接器侧安全配置只读 API 凭证；凭证不进入对话、文档或代码库。
2. 确认 Clarity 已覆盖首页、模板页、创建页、公开表单、发布页与结果页；输入框保持敏感信息遮罩，不能为审计解除遮罩。
3. 使用最近 7 天窗口，按外部会话分层审计；若要定位生成、发布、测试、结果断点，补充可筛选的无 PII 事件标签。

会话列表与遮罩规则参考：[Microsoft Clarity Session List](https://learn.microsoft.com/en-us/clarity/session-recordings/session-list)、[Clarity Client API](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-api)。当前没有可调用的 Clarity 只读连接，因此真实会话审计仍为待验证项。

## 角色与节奏

- 产品经理：维护上述产品合同，拒绝与首成功目标无关的功能扩张。
- UX 负责人：用参考对象审查信息层级、状态反馈和响应式布局；输出可验收的交互说明，而非仅提供视觉偏好。
- 工程负责人：实现、测试，并负责服务端鉴权与数据副作用边界。
- 测试负责人：按两个入口、两个视口、完整闭环回归；发现 P0/P1 时阻止交付。
- SEO / 增长负责人：在技术健康和真实 Clarity 会话证据齐备后，评估入口意图与激活，不能用低样本聚合数据驱动大改。

## 下一轮评测范围

1. 在隔离环境按上述六阶段走一遍“活动报名表”模板入口与首页普通入口。
2. 分别在 390×844 和 1440×900 验证可见性、点击、导航、结果保存和控制台错误。
3. 对任一失败项记录：复现路径、截图、严重度、责任角色、修复后回归证据。
4. 仅当两条路径都通过，才把结果提交给负责人验收；不部署生产。

## 证据与置信度

- 竞品仓库定位及许可证风险：高。链接见“参考对象与借鉴边界”。
- 当前 GenForms 隔离环境首成功闭环能够跑通：高，来自本轮本地全链路验证；发布页首次点击导航曾出现问题，已纳入门禁回归。
- 真实外部用户是否因本轮界面改动提升激活：待验证。必须在可访问的 Clarity 最近 7 天会话中按冷启动审计规则走查，不能凭推断认定。
