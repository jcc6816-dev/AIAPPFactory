# GenForms Clarity 真实 Session 审计（2026-07-06）

## 执行结论

本轮对 Microsoft Clarity 最近 7 天的 **20 条录屏记录进行了全量分层走查**，并对全部有产品意图或异常信号的会话进行深审；同时用 `growth_events`、生产业务事实和已完成的生产 E2E 交叉验证。

最终结论：

1. **没有发现需要立即 Hotfix 的物理故障。** 没有重复出现 404、核心 CTA 失效、页面崩溃、严重 CLS、Rage Click 或 Script Error。生产受控 E2E 也证明创建、发布和提交主链路可工作。
2. **当前统计流量不能代表大量目标用户。** 20 条录屏中，4 条为已知内部/受控访问，1 条为直接访问服务器 IP 的非标准流量，3 条仅停留 1 秒；真正进入创建页的外部高意向搜索用户只有 1 条。
3. **首页并不是这条高意向会话的主要卡点。** 该用户从 Google 进入中文首页，约 6 秒开始 Demo，约 18 秒完成 Demo，约 21 秒进入带 `event-registration` 上下文的 `/zh/forms/new`。
4. **最可信的转化中断发生在创建页的“下一步承诺”上，而不是生成接口失败。** 创建页成功加载模板上下文和 6 字段预览，用户继续点击/输入，但没有触发生成、登录提示、注册或表单创建；约 1 分钟后页面长期隐藏，最终退出。
5. **BetaList 流量以探索和价格评估为主，没有形成创建意图。** 最深的一条 BetaList 会话切换模板分类、查看 Lead Capture/Booking Flow 并进入 Pricing；出现 1 次 Dead Click，但用户随后继续操作，因此它不是阻断性故障。
6. **暂不支持全站重设计。** 当前应该进入 `Iterate with evidence`：先补齐创建页动作埋点，并只做一个针对游客模板预览的单变量实验；同时获得更多可归因目标用户。

## 深审证据

## 三类核心卡点审计

### 1. 阅读与信任流失

- 首页和模板页存在多条 6–33 秒短访，但多数来自 BetaList/Direct 或无动作流量；无法证明某一段文案造成系统性流失。
- BetaList 深度会话会查看模板范围和 Pricing，说明产品类别与价格是其主要评估对象。
- 当前没有足够合格搜索流量支持重写首页或批量改 SEO 页面。

结论：**证据不足，不触发页面重写。**

### 2. 转化意图中断

- 首页高意向路径可在 21 秒左右把用户送到正确创建页；没有看到核心 CTA 失效。
- 唯一高意向外部用户在创建页预览成功后没有触发主创建动作。
- BetaList 的 1 次 Dead Click 后仍继续操作，不能视为阻断。

结论：**最值得验证的是 `/forms/new` 游客态的主动作价值、下一步说明和登录承接。**

### 3. Demo 流程受挫

- 首页 Demo 可开始、完成并传递 `event-registration` 上下文；高意向用户没有在 Demo 阶段失败。
- 创建页没有发生已记录的生成等待或生成失败；当前问题发生在提交生成动作之前。

结论：**暂不优化生成等待动画；先确认用户是否理解并点击主动作。**

## 决策

### 当前状态：Iterate with evidence

不是 `Pass`：外部用户尚未完成首次成功，且两个外部注册账号仍为 0 表单。

不是大规模 `Build`：真正高意向创建会话只有 1 条，没有重复证据支持全站改版。

不是 `Stop`：首页到创建页的意图承接已经真实发生，说明有继续验证的价值。

### 下一步最重要的工作

**让合格游客在上下文已加载的 `/forms/new` 上清楚完成第一个不可逆动作：点击创建/生成，并在登录后恢复该意图。**

这比继续改首页、扩新功能或批量写 SEO 页更重要。

## 建议行动与 Gate

### P0：补齐创建页动作诊断，不改变产品范围

增加或确认以下可区分事件：

- 主按钮进入可视区；
- 主按钮点击；
- 登录提示展示；
- 登录开始 / 登录返回；
- 生成请求开始 / 成功 / 失败；
- 登录后恢复原 template、prompt、source、intent。

目的：下一条高意向会话出现时，能够区分“没看到按钮、看到了但没点击、点击后被登录打断、生成失败”。

### P1：只做一个游客态单变量实验

候选实验：在已加载模板预览的 `/forms/new` 上，把唯一主动作明确成“使用此模板创建表单”，并紧邻说明“下一步可发布并获得分享链接；登录后保留当前模板”。移动端保持主动作可见。

本轮不建议优先添加泛 Prompt 示例，因为关键用户已经带着明确模板进入；先解决“预览之后为什么还要继续”的动作承诺。

### P1：建立合格样本，而不是继续追总 Session

- 使用统一 campaign/source 引入约 20 个确有建表需求的用户；
- Clarity 默认排除内部 source、受控 UID、Admin、原始服务器 IP 和可识别机器人；
- BetaList 与 Organic Search 分开看，不使用总 Session 作为转化率分母。

### Build Gate

满足任一条件才进入 UX 代码修改：

1. 至少 3 个合格外部用户重复出现“预览已加载，但不点击主动作并退出”；或
2. 至少 5 个新外部注册用户仍未创建表单；或
3. 发现 CTA 失效、页面崩溃、生成失败等可复现物理 Bug。

实验验收指标：

- `forms_new_view -> 主动作点击率`；
- `主动作点击 -> 登录提示/生成开始率`；
- `登录返回 -> form_created`；
- 注册后 24 小时首次创建率。

每轮只改一个变量，按 `Pass / Iterate / Stop` 决策。

## 本轮明确不做

- 不因 2 个 Dead Click 重设计首页；
- 不把隐藏页面时长当作高参与度；
- 不把 BetaList/机器人/内部流量混入自然搜索转化率；
- 不把没有发生的生成提交解释成“AI 生成失败”；
- 不在没有重复证据时扩展完整平台或新增 MVP 外模块。

## 最终一句话

**GenForms 目前不是“很多目标用户被坏掉的产品挡住”，而是“合格流量极少；唯一高意向用户顺利到达并看到正确预览，却没有理解或接受创建页的下一步动作”。下一阶段应围绕这一动作做可观测、单变量验证，而不是继续大范围改页面。**
