# GenForms.ai 产品体验与激活主线目标文档

> 版本：2026-06-11
> 适用范围：GenForms.ai MVP 阶段的游客体验、模板体验、创建流程、发布闭环、数据回访与关键事件激活。
> 与 SEO 的关系：SEO 负责把高意图用户带进来；产品体验负责让用户快速发现价值、体验价值、爱上价值，并触发真实业务事件。

## 1. 核心理念

GenForms.ai 的产品体验迭代必须围绕一句话展开：

```text
让客户容易发现价值，让客户容易体验价值，让客户快速爱上价值。
```

这不是单个页面优化，而是与 SEO 并列的产品增长主线。SEO 带来流量后，如果用户没有完成关键事件，增长就没有真正发生。

## 2. 战略目标

让首次访问用户在 30-60 秒内，不登录、不输入、不学习，就能看懂 GenForms.ai 可以帮他完成什么：

- AI 可以生成什么表单。
- 生成后的表单长什么样。
- 表单如何发布和分享。
- 用户如何提交。
- 创建者如何查看数据。
- 为什么这比传统表单工具更省事。

核心原则：

- 先给价值，再要注册。
- 先让用户点击体验，不要求用户先写 prompt。
- 先展示完整结果，再引导用户自定义。
- 先完成一次价值确认，再进入登录、保存、发布或付费。

## 3. 当前判断

GA4 已有关键事件：

- `form_generate`
- `form_publish`
- `form_submit`

如果每天仍有少量访问但没有关键事件触发，说明问题不应只归因于流量少，还要并行检查：

- 用户是否能在登录前看到足够强的产品价值。
- 用户是否知道下一步该点击哪里。
- 模板页、Solution 页和博客页是否把用户引导到同一条激活路径。
- 创建页是否对首次用户过于空白。
- 发布、分享、测试提交和查看数据的闭环是否足够清楚。

### 3.1 2026-06-11 Clarity 早期证据

本阶段新增 Microsoft Clarity，用于观察游客真实行为。当前样本量仍小，且包含 bot 和 Mike 自测数据，所以不能作为最终结论，但可以用于确定下一轮产品体验优先级。

已观察到的信号：

- 首页是主要入口，Clarity Recordings 中 22 个会话里有 21 个从首页进入。
- 首页点击热力图显示，Prompt 区域的主创建按钮获得 12 次点击，占总点击约 32.43%，说明首页首屏主 CTA 有吸引力。
- Prompt 输入框只有 1 次点击，说明游客阶段让用户自己输入 prompt 的摩擦仍然偏高。
- 首页 Scroll 显示，大量用户没有继续滚到下方内容，模板、技能、价格、博客等下半部分不能承担主要首触转化责任。
- `/forms/new` 有访问记录，但热力图数据不足；已有 Recordings 显示部分用户从首页进入创建页后很快退出，说明创建页第一屏仍是重点排查对象。
- 一个真实手机端用户已从 Betalist 来源注册，但早期手机端创建页预览区不足，这提示移动端创建体验必须作为 P0 验证点。

因此，当前产品体验判断不是“首页完全无效”，而是：

```text
首页能够吸引部分用户点击，但用户进入创建流程后，还没有稳定完成从兴趣到 form_generate 的价值确认。
```

下一轮产品体验优化必须优先服务这条路径：

```text
首页/内容页点击 -> 免输入体验 -> 带上下文进入创建页 -> 看到生成结果 -> form_generate
```

### 3.2 2026-06-20 Google 点击与 Pricing 行为观察

Mike 在 GSC 与 Clarity 中发现一个来自 Google 的高意向真实访客会话：

- 来源：Google organic，入口为首页 `genforms.ai`。
- 设备：移动端，384 x 690，Chrome Mobile，Android。
- 地区：Singapore。
- 行为：用户进入首页后点击 `Event Booking` 场景按钮，随后多次点击 `Pricing`，最终看到了 `$19` 价格信息。
- 暴露问题：移动端 Pricing 锚点初始存在落位不稳定，点击后可能没有准确滚到价格区。2026-06-20 Codex 已修复并部署 `#pricing` 锚点延迟校准，生产验证英文 `/ #pricing` 与中文 `/zh#pricing` 均可正确落到价格区。

当前判断：

- 这是一个高价值的搜索访客样本，说明 Google 带来的用户可能会沿着“具体场景 -> 价格判断”的商业路径行动。
- 样本量仍然太少，不能把未注册/未购买直接归因为 `$19` 价格太高。
- Mike 对“首页太复杂”的直觉需要保留为后续观察假设，但暂不建议仅凭 1 个会话大改首页。

后续观察假设：

- 如果更多 Google 访客重复出现 `Event Booking` 或其他场景点击后寻找 Pricing，首页应进一步收敛到“选场景、看价格、开始创建”三条主路径。
- 如果 Pricing 后仍没有 `signup_started` 或创建行为，应优先检查信任证明、免费开始入口、模板承接和移动端 CTA，而不是立即降价。
- 首页复杂度评估需要至少 5-10 个真实 Google/organic Clarity 会话后再做较大调整。

## 4. 产品体验分层

### 4.1 发现价值

目标：用户进入首页、模板页、Solution 页或博客页后，能立刻理解 GenForms.ai 的核心价值。

要求：

- 页面主 CTA 聚焦到一个动作，例如 `Try this form`、`Use this template` 或 `Create an AI form`。
- 首屏或关键区域展示真实产品状态，而不是只讲功能。
- 每个高意图 SEO 页面都要连接到具体表单场景，而不是泛泛跳转到首页。

### 4.2 体验价值

目标：游客不登录、不输入，也能通过点击体验一条完整产品链路。

建议体验路径：

```text
选择场景 -> 一键 Demo -> 自动生成表单 -> 预览表单 -> 模拟发布 -> 模拟提交 -> 查看示例数据
```

要求：

- Demo 不依赖用户输入 prompt。
- Demo 应该展示真实尺寸预览，例如 Phone / Desktop、Step Flow / Long Flow。
- Demo 结束时给出明确下一步：`Customize this form` 或 `Create my form`。

### 4.3 爱上价值

目标：用户体验后产生“我也能马上用”的感觉。

要求：

- 模板详情页的 `Use this template` 必须把模板上下文带入创建流程。
- Solution 页的 Demo 必须与当前场景一致。
- 创建页要有推荐 prompt、一键示例和下一步提示。
- 生成成功后只突出最重要动作：发布表单。

### 4.4 留下价值

目标：用户不只生成表单，还能进入发布、提交、数据和自动化闭环。

要求：

- 发布后突出复制链接、二维码和测试提交。
- 测试提交后引导查看数据中心。
- 数据中心展示提交结果、导出、Webhook 或下一步自动化。
- 免费用户看到升级价值时，应来自真实使用需求，而不是强制打断。

## 5. 核心激活漏斗

现阶段建议把产品体验漏斗定义为：

```text
page_view
-> demo_start
-> demo_complete
-> template_use_click
-> form_generate
-> form_publish
-> form_submit
```

已实现或已配置的关键事件：

- `form_generate`
- `form_publish`
- `form_submit`

建议补充的游客前置事件：

- `demo_start`
- `demo_complete`
- `template_use_click`

这些事件的作用不是追求数据好看，而是定位用户到底卡在“看见价值之前”、 “体验价值过程中”还是“进入真实创建之后”。

## 6. 阶段安排

### 阶段 A：游客极速体验

目标：让游客不用输入、不用登录，也能完整看懂产品。

优先任务：

- 首页增加一键体验 AI 表单生成模块。
- 模板详情页增加自动 Demo 或高保真互动预览。
- Solution 页增加场景化 Demo。
- Demo 覆盖生成、预览、发布、提交和数据结果。
- 增加 `demo_start`、`demo_complete`、`template_use_click` 事件。

验收标准：

- 游客可以在 30-60 秒内完成一次只读 Demo。
- Demo 结束后有清晰的创建入口。
- GA4 或站内事件能看到 Demo 漏斗。

### 阶段 A1：首页免输入首屏体验

目标：把首页从“让用户输入 prompt”升级为“让用户先点一个场景，马上看到结果”。

建议形态：

- 在首页 Prompt 输入区附近前置 3 个高频场景按钮：
  - `Lead Capture`
  - `Event Registration`
  - `Customer Feedback`
- 用户点击场景按钮后，前端直接进入 Demo 生成状态，不要求输入、不要求登录。
- 右侧 Mockup/Preview 区不只是展示，应成为可点击的体验区域。
- Demo 完成后提供清晰下一步：
  - `Customize this form`
  - `Use this template`
  - `Create my own form`

验收标准：

- 首页首屏能在不输入的情况下触发 `demo_start`。
- Demo 完成后触发 `demo_complete`。
- 点击后能带 `prompt`、`template` 或 `scenario` 上下文进入 `/forms/new`。
- Clarity 中首页 Dead Click 占比下降，Mockup/场景按钮点击占比上升。

### 阶段 B：全站 CTA 与入口统一

目标：所有流量入口都导向同一套激活路径。

优先任务：

- 首页、模板页、Solution 页、博客页统一 CTA 语义。
- 每个博客页只放一个主 CTA。
- 每个模板页默认导向对应模板创建。
- 每个 Solution 页导向对应场景 Demo 或创建流程。

验收标准：

- 用户从任意高意图页面进入后，不需要思考下一步。
- 页面 CTA 与页面搜索意图一致。
- 内链不分散主目标。

### 阶段 B1：创建页首屏减负

目标：让用户从首页、模板、Solution 或博客进入 `/forms/new` 后，不再面对空白或需要自行理解的界面。

要求：

- `/forms/new` 必须识别并消费来源参数，例如：
  - `template`
  - `prompt`
  - `source`
  - `scenario`
- 有上下文时，创建页首屏应表达“已经为你准备好了”，而不是空状态。
- 推荐 prompt、模板标题、预览区域和生成按钮必须在首屏形成一条清晰路径。
- 手机端优先保证用户能看到预览或结果状态，编辑器和高级配置可以折叠到次级。
- 首页主按钮或其他 `prompt-only` 入口不能只把 prompt 带入创建页。若游客无法直接真实生成，应先用轻量规则把 prompt 映射到最接近的模板，并带上 `template` 参数，让用户进入创建页后直接看到匹配场景预览。
- 预览设备默认应尽量匹配访问设备：桌面访客默认看 Desktop 预览，移动端访客默认看 Phone 预览。用户仍可手动切换设备模式。

验收标准：

- 从首页一键 Demo、模板详情页、Solution 页、博客页进入 `/forms/new` 时，页面不是空白开始。
- 从首页主按钮输入“科技峰会门票”等 prompt 进入 `/forms/new` 时，不能只显示通用“快速体验演示表单”，应显示匹配的活动报名/门票表单预览。
- 真实移动端能在首屏看到“下一步该做什么”。
- 桌面端进入创建页时，默认预览不应强行使用 Phone 模式；移动端进入时默认展示 Phone 模式。
- `template_use_click -> form_generate` 的转化开始可被 GA4 观测。

### 阶段 C：登录后发布闭环

目标：让注册用户快速完成 `form_generate -> form_publish -> form_submit`。

优先任务：

- 创建页增加推荐 prompt 和一键示例。
- 生成成功后突出发布按钮。
- 发布成功后突出复制链接、二维码和测试提交。
- 提交后引导查看数据中心。
- 数据中心提供下一步自动化或导出提示。

验收标准：

- 新用户能在一次会话内完成生成、发布和测试提交。
- 关键事件可被 GA4 或站内事件捕获。
- 新用户首页或控制台不再给人“空”的感觉。

### 阶段 D：移动端创建体验专项

目标：确保真实手机端用户也能完成从 Demo 到生成的价值确认。

背景：

- Clarity 早期数据中已有真实手机端用户从外部来源进入并注册。
- 早期手机端创建页预览区不足，可能影响用户对“生成结果”的感知。

优先任务：

- 首页移动端首屏保留清晰主 CTA 和一键场景入口。
- `/forms/new` 移动端优先展示预览、生成状态和下一步按钮。
- 模板详情页手机模式避免滚动条、遮挡和预览内容过小。
- 发布页手机端复制链接、二维码和测试按钮要容易触达。

验收标准：

- 移动端用户能在一次会话中完成 `demo_start -> demo_complete -> form_generate`。
- Clarity mobile recordings 中不再出现“进入创建页后立刻退出且无明确点击”的高频模式。

### 阶段 E：发布与数据闭环

目标：让用户不仅生成表单，还能感受到“发布后能收数据”的完整价值。

优先任务：

- 发布成功页突出：
  - 复制分享链接
  - 手机扫码测试
  - 测试你的表单
  - 查看提交数据
- 数据中心空状态要给出具体下一步，而不是只显示空表格。
- 用户完成第一次测试提交后，引导其查看提交记录和 Webhook/导出能力。

验收标准：

- `form_publish -> form_submit` 可以被追踪。
- 新用户能明确知道发布后下一步该做什么。
- 数据中心空状态能引导产生第一条测试数据。

## 8. 不做什么

为了避免再次变成零散优化，本主线暂不做：

- 单纯为了好看而做的大规模视觉重设计。
- 与表单生成、发布、提交、数据查看无关的新模块。
- 需要复杂后端权限、支付、账单或数据库迁移的大改动。
- 只增加解释文字、不改善用户实际路径的页面堆料。
- 要求游客先注册、先输入、先学习才能看到价值的体验设计。

## 9. 决策准则

任何产品体验任务进入开发前，都必须回答：

1. 它帮助用户更容易发现价值了吗？
2. 它帮助用户更容易体验价值了吗？
3. 它帮助用户更快触发 `form_generate`、`form_publish` 或 `form_submit` 了吗？
4. 它是否能被事件追踪或人工验证？
5. 它是否与当前 MVP 实际能力一致？

如果以上问题无法回答清楚，任务应回到方案阶段，不应进入实现。

## 10. 当前 P0/P1/P2 工作队列

### P0：先补上游客价值确认

1. 首页一键 Demo 场景前置。
2. `/forms/new` 带上下文进入，不再空白开始。
3. 移动端创建页优先展示预览和下一步按钮。
4. 首页主按钮的 `prompt-only` 入口增加轻量 prompt-to-template 映射，游客进入创建页时直接看到匹配模板预览。
5. 创建页预览设备默认跟随访问设备：桌面默认 Desktop，移动端默认 Phone。
6. 关键事件确认：`demo_start`、`demo_complete`、`template_use_click`、`form_generate`。

### P1：强化高意图页面转化

1. 模板详情页游客可交互填写和模拟提交。
2. Solution 页 CTA 与当前场景强绑定。
3. 博客页只保留一个明确主 CTA，并透传来源参数。
4. 首页 Mockup 区减少不可点击误导，避免 Dead Click。

### P2：发布后留存与商业化

1. 发布成功页强化测试表单、复制链接、二维码和查看数据。
2. 数据中心空状态改成下一步引导。
3. 登录后 User Center 从“信息页”升级为轻量工作台。
4. 免费额度和升级提示从真实使用场景中出现，避免生硬打断。

## 11. 数据验证口径

后续每轮体验优化都应至少选择一种验证方式：

- GA4：观察关键事件数量和来源参数。
- Clarity：观察 Recordings、Dead Click、Quick Back、Scroll、Mobile 行为。
- 后台数据：观察新用户是否创建、发布、提交测试数据。
- 人工走查：桌面和手机端各走一遍首页、模板页、创建页、发布页和提交页。

判断方式：

- 有曝光没点击：优先看 SEO 标题、description 和搜索意图匹配。
- 有页面访问没 Demo：优先看首屏价值表达和 CTA。
- 有 Demo 没 Generate：优先看创建页上下文衔接。
- 有 Generate 没 Publish：优先看发布按钮、登录阻力和保存逻辑。
- 有 Publish 没 Submit：优先看发布页测试引导和分享链路。
