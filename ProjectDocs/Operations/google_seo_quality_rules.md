# GenForms.ai Google SEO 质量与合规规则

> 版本：2026-06-04
> 用途：作为 GenForms.ai 后续做 SEO、博客、Solution 页面、Use Case 页面和模板页扩展时必须遵守的质量规则。
> 依据：Google Search Central 官方文档，包括 Search Essentials、Spam Policies、Helpful Content、Canonical、Structured Data Guidelines。

## 1. 核心原则

Google 不禁止使用 AI 辅助写内容，也不禁止持续增加页面。真正高风险的是：

- 为了操纵排名而批量生成低价值页面。
- 内容对真实用户没有帮助，只是堆关键词。
- 多个页面高度相似，只是替换行业、地区、关键词。
- 页面承诺了功能，但用户实际无法完成。
- 结构化数据、标题、日期、作者等信息误导搜索引擎或用户。

GenForms.ai 的 SEO 策略必须围绕“真实用户能完成一个表单工作流”展开，而不是围绕“尽快堆很多索引页”展开。

## 2. 内容发布节奏规则

### 推荐节奏

- 每周新增 2 篇高质量博客，优先英文。
- 每周新增或优化 1-3 个 Solution / Use Case / Template 页面。
- 每周至少优化 1 个旧页面，优先处理已有展示但点击率低的页面。
- 不建议一天批量上线几十篇相似文章或页面。

### 为什么不能粗暴批量发布

Google 的风险点不是“数量多”本身，而是“规模化低价值内容”。如果大量页面都是模板化、重复、薄内容，可能被视为 scaled content abuse。

因此我们采用“少量、高意图、可验证、可转化”的发布节奏。

## 3. 每篇内容必须满足的质量标准

每篇博客或 SEO 页面上线前，必须通过以下检查：

- 有明确搜索意图：用户为什么会搜这个词？
- 能解决一个真实问题：读完后用户知道下一步怎么做。
- 与 GenForms.ai 当前 MVP 能力匹配，不夸大未稳定上线的能力。
- 有原创判断、流程、字段建议、错误提醒或产品实践，而不是改写竞品文章。
- 至少链接到 1 个相关 Use Case / Solution / Template 页面。
- 只有 1 个主要 CTA，避免多目标分散。
- 标题和 description 能准确概括页面内容，不夸张、不标题党。
- 内容没有明显事实错误、拼写错误、AI 腔或空泛段落。
- 页面显示发布日期；如果只是小改，不伪装成重大更新。

## 4. 禁止内容类型

以下内容不允许发布或收录：

- 大量 AI 自动生成但未经人工审核的文章。
- 多个页面只替换关键词，例如 “AI form builder for X industry”，正文结构和内容几乎一样。
- 没有实际产品能力支撑的文章，例如把实验性 Skill 写成正式企业能力。
- 纯资讯搬运、竞品内容改写、搜索结果拼接。
- 没有正文价值的薄页面，仅靠标题、关键词和 CTA。
- 标题承诺“完整指南”“最佳工具”“权威报告”，但内容没有足够证据或分析。
- 为了让页面显得新鲜而只改日期、不实质更新内容。
- 隐藏给用户不可见、但给搜索引擎可见的关键词或结构化数据。

## 5. AI 内容使用规则

AI 可以用于：

- 生成初稿。
- 提供文章结构。
- 扩展字段清单、常见错误、操作步骤。
- 生成多语言草稿。
- 做内部链接建议。

AI 不可以直接决定发布。每篇 AI 辅助内容上线前必须人工审核：

- 是否真的解决用户问题。
- 是否包含 GenForms.ai 自己的产品实践。
- 是否有可操作步骤。
- 是否有错误、夸大、重复和无意义段落。
- 是否存在“看起来很多字，但没有信息增益”的问题。

判断标准：如果这篇文章去掉关键词后仍然值得用户阅读，才可以发布。

## 6. 页面相似性与 Duplicate / Doorway 风险

### 允许

- 不同行业的 Solution 页面，只要字段、流程、CTA、FAQ、用户场景确实不同。
- 英文和中文页面并存，只要 canonical、hreflang 和语言路径清晰。
- 模板页、Use Case 页、博客互相链接，形成清晰内容层级。

### 禁止

- 为每个近似关键词生成一个几乎一样的页面。
- 只改城市、行业、职位、表单名称，正文大部分相同。
- 多个页面都把用户导向同一个创建入口，但页面本身没有独立价值。
- `/en/...` 与 `/...` 同时作为英文索引主路径造成重复。

当前 GenForms.ai 的英文 canonical 策略：

- 英文主路径：`/...`
- 中文路径：`/zh/...`
- `/en/...` 只作为兼容路径，不作为 sitemap 主索引目标。

## 7. 结构化数据规则

结构化数据必须真实对应页面可见内容。

允许使用：

- `BlogPosting`：博客文章。
- `SoftwareApplication`：产品、Solution、Use Case、模板页。
- `FAQPage`：页面上真实显示 FAQ 时使用。
- `BreadcrumbList`：页面层级导航。

禁止：

- 标记用户看不到的内容。
- 用不存在的评分、评论、价格、作者信息。
- 页面是普通文章，却标成不相关类型。
- FAQ 结构化数据和页面可见 FAQ 不一致。

结构化数据正确不保证一定展示富摘要，但错误或误导可能导致富摘要资格丢失，甚至触发结构化数据相关问题。

## 8. 技术 SEO 基线

所有可索引页面必须满足：

- 返回 HTTP 200。
- Googlebot 可访问，不被 robots.txt、登录、noindex 阻挡。
- 页面有可索引正文，不是空壳或纯客户端不可读内容。
- 有唯一 title 和 meta description。
- 有 canonical。
- 多语言页面有正确 hreflang。
- sitemap 只放希望 Google 发现和索引的 URL。
- 不把 HTTP URL 放进 sitemap 或 hreflang，统一使用 HTTPS。
- 发布后用 GSC URL Inspection 检查重点页面。
- 每次新增或修改 SEO 页面后，必须运行生产 SEO Gate：`./Code/scripts/verify-production-seo.sh https://genforms.ai`，确认 sitemap、canonical、hreflang、结构化数据和旧 `/en` 兼容路径没有异常。

## 9. 外链与推广规则

允许：

- Product Hunt、工具目录、社区讨论、真实教程、行业博客引用。
- 自己发布案例、指南、对比工具、资源页，吸引自然引用。
- 使用 UTM 参数跟踪来源。

禁止：

- 购买传递排名权重的链接。
- 大量低质量目录批量提交。
- 互链交换只为排名。
- 自动生成外链。
- 在社区中生硬刷链接。

外链策略优先追求真实推荐和相关性，而不是数量。

## 10. GenForms.ai 发布前 SEO 检查清单

每个新页面上线前，Codex 或内容 Agent 应检查：

1. 这个页面对应哪个关键词和搜索意图？
2. 它是否服务“搜索曝光 → 点击创建 → 注册 → 创建表单 → 发布表单 → 收到提交 → 升级付费”漏斗？
3. 这篇内容是否比搜索结果里的普通文章多了 GenForms.ai 自己的流程、字段建议或产品实践？
4. 是否有内部链接到相关 Use Case / Solution / Template？
5. 是否只有一个清晰 CTA？
6. 是否有 title、description、canonical、发布日期和结构化数据？
7. 是否避免夸大尚未成熟的功能？
8. 是否不是批量替换关键词生成的相似页面？
9. 是否已经进入 sitemap？
10. 是否需要用户在 GSC 请求索引？

## 11. 后续执行红线

后续增长动作必须遵守：

- 不追求一天大量上线。
- 不发布未审核 AI 文章。
- 不发布没有真实产品落点的泛 AI 内容。
- 不用虚假日期、虚假评分、虚假评论。
- 不让页面标题、结构化数据和正文表达不一致。
- 不为了 SEO 牺牲用户实际体验。

如果某个页面无法明确回答“用户读完后能做什么”，则暂缓发布。
