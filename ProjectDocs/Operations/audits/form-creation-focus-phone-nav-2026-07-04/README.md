# GenForms 新建表单聚焦体验验收

日期：2026-07-04

## 验收范围

- 页面：`/forms/new?template=event-registration`
- 已保存表单编辑页：`/forms/{id}`
- 桌面端：1440 x 900
- 移动端：549 x 744
- 本轮只处理新建页操作聚焦、Phone 预览完整性和保存后顶部导航重叠，不扩展 MVP 范围。

## 用户反馈与根因

1. 新建页不知道从何下手：AI 助手、预览模式、主题、布局、结构和下一步操作同时出现，主任务不突出。
2. Phone 模式首屏显示不完整：设备预览沿用桌面内容高度，页面与设备内部同时滚动。
3. 保存草稿后一级菜单重叠：顶部导航采用绝对居中，右侧保存与发布操作进入同一水平空间。

## 本轮修改

- 草稿生成后默认进入聚焦预览，AI 助手、Outline、JSON、主题和布局设置不再常驻。
- 桌面端只保留一个主 CTA：`Publish form`；`Save draft` 为次要操作。
- `Edit with AI` 和 `Customize` 作为按需入口，避免首次进入时暴露全部能力。
- 移动端只保留 `More` 和一个主 CTA，底部操作区固定且不遮挡预览。
- Phone 预览采用视口约束高度和固定设备比例，表单内容在设备内部滚动。
- 保存后的顶部栏改为三列网格；移动端长期功能菜单独立为第二行，避免与保存、发布操作争抢空间。
- 1440 宽度下隐藏低优先级的语言、主题和用户控制，超宽屏再显示。

## 验收结果

### 桌面端

- 页面首屏视觉中心为真实表单预览，右侧 Action Rail 只突出发布。
- Phone 设备框完整显示，高度 580px，底部未被裁切。
- 保存后 `Design / Data / Analytics / Publish` 与 `Save Draft / Publish` 无碰撞。
- 1440 宽度下功能导航最右侧约为 896px，保存操作从约 1167px 开始，保留了稳定间隔。

### 移动端

- 549 x 744 下 Phone 设备框尺寸约为 284 x 484px，底部约为 659px。
- 固定操作区从约 671px 开始，设备预览与操作区之间仍有间隔。
- 页面文档高度等于视口高度，不需要为了看到完整设备框而滚动页面。
- 首屏只有 `Publish form` 一个主 CTA；高级设置进入 `More / Customize`。

### 可访问性与多语言

- 使用原生按钮和现有 Sheet、Select 等组件，保留键盘操作能力。
- 图标操作保留可访问名称；移动端保存按钮收窄时不丢失语义。
- 聚焦布局使用弹性空间和截断规则，可承受中文、西班牙语等较长文案。
- 本轮未进行屏幕阅读器全流程、软键盘弹出和真实日语/西班牙语逐页验收，属于后续设备测试范围。

## 工程验证

- `npm run test`：81 个测试文件、383 项测试全部通过。
- `npm run build`：通过，包含 TypeScript 和 Next.js 生产构建检查。
- `git diff --check`：通过。
- React 检查：未新增条件 Hook、非语义点击区域或不稳定列表 key。

## 风险与边界

- 已保存表单编辑器仍保留完整 Design 工作台，这是进入深度编辑后的能力区，不与新建页聚焦模式混用。
- 本轮没有重新设计发布成功、测试提交和结果页；它们沿用 First Success Loop 的既有实现。
- 若后续在 320px 极窄设备或浏览器软键盘开启状态发现拥挤，应以折叠次要操作为主，不恢复多行常驻工具栏。

## 验收结论

通过。用户指出的三个问题均已处理，可以在本地测试环境继续体验复核。
