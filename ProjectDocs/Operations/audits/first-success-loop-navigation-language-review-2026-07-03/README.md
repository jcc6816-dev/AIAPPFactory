# GenForms 首次成功闭环导航与语言复核

日期：2026-07-03  
复核方式：本地页面只读走查，未修改产品代码。

## 复核范围

1. 表单草稿生成完成
2. 发布成功
3. 第一条测试结果
4. 第一条测试结果移动端
5. 英文界面的未生成上下文状态

## 总体判断

当前实现存在明显的信息架构冲突，暂不应按“设计验收通过”处理。

`Design / Data / Analytics / Publish` 是持久的产品功能导航；`Context / Generate / Publish / Test / Result` 本应表达一次性的首次成功进度，但目前也采用了完整横向胶囊导航的视觉形式。两套结构连续出现、权重接近，并且重复使用 `Publish`，导致用户无法快速判断哪一层是页面位置、哪一层是任务进度。

移动端问题更明显：两排胶囊导航占据首屏顶部，下面再接 Context Banner，共有三层状态信息，挤压了真正的任务内容。

## 分步骤结论

### 1. 表单草稿生成完成

健康度：有明显问题。

- 顶部 `Design` 高亮，下一排 `Generate` 高亮，同时右侧又出现 `Draft ready / Publish form`。
- 用户同时接收到“当前在设计页”“当前在生成步骤”“下一步发布”三套状态信号。
- 流程条中的项目不可点击，但外观与上方可点击导航高度相似，存在错误操作暗示。
- 页面内还有预览工具栏和表单内部的 `Next`，首屏操作层级过多。

证据：`01-generated-draft.png`

### 2. 发布成功

健康度：部分可用，但层级冲突仍在。

- 一级 `Publish` 与流程中的 `Publish` 同时高亮，是最直接的重复命名和重复选中状态。
- 发布结果和“发送免费测试”的主任务本身清晰，但顶部两套导航削弱了成功状态。
- 下方仍保留较大的集成与技能内容，用户继续向下阅读时容易从“完成首次测试”偏离到高级配置。

证据：`02-publish-success.png`

### 3. 第一条测试结果

健康度：内容清晰，导航定义冲突。

- 一级导航高亮 `Data`，流程条高亮 `Result`。两者语义并非完全冲突，但界面没有解释“Result 是首次成功阶段，Data 是长期功能区域”。
- 第一条测试结果、Test/Saved 标识和分享公开表单动作清晰。
- Action Rail 中“每个状态只突出一个主操作”属于设计说明，不应作为面向用户的产品文案长期显示。
- 页面首次加载时先短暂显示普通数据表，再切换为第一条结果聚焦视图，存在状态闪烁。

证据：`03-first-result.png`

### 4. 第一条测试结果移动端

健康度：主要内容可用，顶部结构拥挤。

- `Design / Data / Analytics / Publish` 与 `Context / Generate / Publish / Test / Result` 连续占据两行。
- Context Banner 再占一行，导致用户在看到成功结果前需要先处理三层导航和状态信息。
- 底部主操作清晰，但顶部重复层级让页面显得像后台导航和新手教程叠加在一起。

证据：`04-first-result-mobile.png`

### 5. 英文界面的未生成上下文状态

健康度：不通过。

- 页面语言为英文，但 Context Banner 的推荐字段显示中文。
- 根因已定位：`forms/new/page.tsx` 构建 `initialContextSummary` 时始终读取 `templateDefinition.formSchema`，没有在英文界面使用 `formSchemaEn`。
- 英文页面的主题切换按钮 `aria-label` 仍硬编码为中文，属于无障碍语言泄漏。
- 生成完成后推荐字段会被英文生成结果覆盖，因此问题具有状态差异，容易在普通验收中漏掉。

证据：`05-english-context-language-leak.png`

## 问题优先级

### 必须解决

1. 重新定义首次成功进度的视觉角色，不能继续作为第二套同权重横向导航。
2. 修复英文未生成状态直接读取中文模板字段的问题。
3. 修复英文页面主题切换按钮的中文无障碍标签。
4. 消除第一条结果从普通数据表切换到聚焦结果时的闪烁。

### 后续优化

1. 减少 Context Banner、进度状态和功能导航的重复信息。
2. 移除 Action Rail 中解释设计原则的元文案。
3. 在发布成功后的首屏之后弱化高级集成内容，避免抢走“发送免费测试”的主任务。

## 初步方向

- 保留 `Design / Data / Analytics / Publish` 作为表单创建后的长期功能导航。
- 将首次成功五状态改为轻量的激活进度或下一步提示，而不是第二套导航；完成后应收起或消失。
- `/forms/new` 尚未形成持久表单时，不应同时呈现完整的长期功能导航和完整的首次成功导航。
- 移动端优先显示当前任务和唯一下一步，只保留一处紧凑进度入口。

## 证据限制

- 本轮没有进行键盘和屏幕阅读器完整测试，因此无障碍部分仅记录可从 DOM 与界面确认的风险。
- 本轮未修改代码，也未验证调整后的视觉方案。
