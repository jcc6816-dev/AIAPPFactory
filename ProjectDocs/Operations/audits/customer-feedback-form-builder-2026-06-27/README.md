# Customer Feedback Form Builder 页面复核

日期：2026-06-27

页面：`http://localhost:3100/zh/use-cases/customer-feedback-form-builder`

## 审计范围

- 桌面端首屏定位、视觉层级与 CTA
- 移动端首屏响应式表现
- CTA 到预配置创建页的产品承接
- 产品事实边界、字段清单与用户可见文案
- 基础可访问性与 SEO 结构检查

## 用户主任务

用户希望快速创建一份简短的客户反馈表，通过链接或二维码发布，收集评分和改进意见，并在后台查看、导出或继续流转回复。

## 步骤与健康度

1. 桌面端落地页首屏：基本健康。H1、主 CTA 和反馈表预览匹配场景，但 CTA 辅助信息偏弱，二级 CTA 使用外链图标与站内锚点行为不一致。
2. 移动端落地页首屏：需要修改。主 CTA 清楚，预览可见，但 H1 出现严重孤行，最后一个“器”单独换行，首屏显得不完整。
3. CTA 到创建页：部分健康。`template=satisfaction-survey`、`source=usecase_customer-feedback-form-builder`、`intent=customer_feedback` 正确传递，创建页加载了客户满意度调查；移动端创建工作台顶部控制区拥挤、部分按钮被裁切，且视觉方向仍显示“高端活动转化”，与客户反馈场景不匹配。

## 优点

- 页面定位明确，没有把 GenForms 描述成专业 NPS 或企业 CX 分析平台。
- 当前承诺与产品事实一致：AI 生成、公开链接、二维码、数据面板、CSV、Webhook/Bot 后续流转。
- 推荐字段覆盖评价对象、总体评分、评分原因、优点、改进项、反馈类别、再次使用意愿、可选联系方式和回访许可。
- CTA 已进入预配置创建路径，创建页首题为“你使用的是哪项产品或服务？”，不是泛化空白表单。
- 页面仅有一个 H1，canonical、FAQPage、SoftwareApplication、BreadcrumbList 均存在。

## 必须修改

1. 删除或改写面向内部 SEO/产品团队的文案：`搜索意图`、`AI 起点`、`为什么需要这个入口`、`用户搜的不是产品名，而是具体问题`、`意图匹配`、`可验证卖点`、`不是静态营销页，是可进入产品的场景入口`。这些话解释的是页面制作逻辑，不是用户收益。
2. 不要向访客展示“内容计划”占位卡。相关指南未发布时隐藏该区块；发布后只展示真实可点击内容。
3. 修复移动端 H1 排版，使用更小字号和均衡换行，避免单字孤行。
4. 客户反馈模板进入创建页后，不应默认显示“高端活动转化”视觉方向。应切换为客户反馈适用的中性、可信方向。

## 可选优化

- 将二级 CTA 的外链图标改为向下箭头或字段列表图标，准确表达页内跳转。
- 首屏预览的示例意见从“系统运行非常顺畅，极力推荐！”改为包含一个具体改进点的真实反馈，强化“可执行反馈”而非五星好评展示。
- 将 `Webhook-ready` 改为更自然的中文，例如“可通过 Webhook 继续流转”。
- 移动端创建页隐藏次要工具，保留场景名称、预览和主要创建动作，减少顶部裁切和横向工具条负担。

## 可访问性风险

- 页内锚点使用外链图标，可能让键盘和辅助技术用户误判跳转行为。
- 模板预览中的星级仅以视觉字符呈现；若该区域可交互，需要补充明确标签、选中状态和键盘操作。
- 截图无法确认完整键盘焦点顺序、焦点可见性、屏幕阅读器播报和实际色彩对比数值，需另行测试。

## 上线判断

暂不建议上线。产品定位与 CTA 参数正确，但内部策划文案公开展示、内容计划占位、移动端 H1 孤行和创建页场景默认值不匹配，会明显削弱可信度与转化。
